01
Problem statement
The trust gap
Traditional model — broken
Operator → “My router was online 24/7”
Company  → “Okay, we trust you”
✗  No verifiable proof of uptime
✗  Operators can lie to earn more
✗  Companies can underpay in disputes
✗  No neutral audit trail
✗  Every payment requires trust
RouterPulse model — trustless
✓  Signed heartbeat every N seconds on-chain
✓  Timestamp stored in PDA — immutable
✓  Rewards auto-calculated from verifiable proof
✓  Anyone can audit any router’s history
✓  Blockchain is the neutral source of truth
Key insight: Clock::get() is set by Solana validators — impossible to forge by any caller. This single fact makes the entire protocol trustless.
Real-world analogy
Heartbeat = router punching a timestamped attendance card that neither operator nor company can alter after the fact. The validator signs it.

03
Core instruction
Heartbeat data flow
STEP 01
Router sends signed heartbeat tx
program.methods.heartbeat().accountsPartial({router,protocol,owner}).rpc() — signed by owner keypair
↓
STEP 02
Anchor validates all accounts
Seeds + bump re-derived and compared. has_one = owner enforced. Status != Suspended or Decommissioned.
↓
STEP 03
Clock::get() — tamper-proof timestamp
elapsed = now − last_heartbeat. If elapsed == 0 → HeartbeatTooSoon (same-block replay blocked).
↓
STEP 04
uptime::calculate(score, elapsed, interval)
Pure function. On time → +1 capped at 100. Late → −10 floored at 0. missed_heartbeats++.
↓
STEP 05
Auto-suspend check
score ≤ 20 AND Active → status = Suspended. RouterSuspended event emitted. Router stops automatically.
↓
STEP 06
State committed + event emitted
last_heartbeat = now. heartbeat_count += 1 via checked_add. HeartbeatReceived event indexed by RPC nodes.
First heartbeat special case
heartbeat_count == 0 → no timing check. Transitions Inactive → Active. Sets last_heartbeat = now. No penalty.
if router.heartbeat_count == 0 { router.status = RouterStatus::Active; router.last_heartbeat = now; // no penalty on first heartbeat } else { let elapsed = now .checked_sub(router.last_heartbeat) .ok_or(RouterPulseError::InvalidTimestamp)?; require!(elapsed > 0, HeartbeatTooSoon); let result = uptime::calculate( router.uptime_score, elapsed, interval ); }
Why Clock::get() and not a passed argument? Caller can forge any argument value. Validators set the clock — the only unforgeable time source in a Solana program.
Two-layer replay protection
Layer 1: elapsed > 0 blocks same-block replay. Layer 2: last_heartbeat = now ensures every future call measures elapsed from current validated time.
04
Economic engine
Reward claim flow
CHECK 01
Eligibility gate
status == Active • heartbeat_count > 0 • elapsed > 0 • reward > 0 • vault balance ≥ amount
↓ all pass
CALC 02
Uptime percentage from history
uptime_pct = (heartbeat_count − missed) × 100 ÷ heartbeat_count
↓
CALC 03
Base reward × reliability
base = elapsed × reward_rate  •  final = base × uptime_pct ÷ 100
↓
TRANSFER 04
Direct lamport transfer from vault PDA
vault.lamports −= amount • owner.lamports += amount • atomic — no partial transfer
↓
STATE 05
Update state + emit event
router.total_rewards += amount • last_claim_time = now • protocol.total_distributed += amount
// uptime percentage uptime_pct = (heartbeat_count - missed_heartbeats) × 100 ÷ heartbeat_count // base reward base = elapsed_secs × reward_rate // scale by reliability reward = base × uptime_pct ÷ 100
// worked example elapsed = 3600s   rate = 1000 lam/s uptime = 80% base = 3,600,000 lamports reward = 2,880,000 lamports
Why direct lamport mutation not CPI transfer?
system_program::transfer requires the sender to sign. A PDA has no private key — it cannot sign. Direct lamport manipulation works cleanly for in-transaction balance moves.
Why last_claim_time not last_heartbeat? last_heartbeat resets every 5 minutes. Using it forces claiming after every heartbeat. last_claim_time lets days of rewards accumulate — practical for operators.

06
Business logic
Uptime score algorithm
// on-time heartbeat new_score = min(100, score + 1) // late heartbeat (elapsed > interval) new_score = max(0, score - 10) // auto-suspend score ≤ 20 AND status == Active
Asymmetric by design: +1 on time, −10 late. One miss wipes 10 recoveries. Operators cannot game with burst heartbeats after downtime.
saturating_sub for score
Score can safely floor at 0. saturating handles without error. No need to abort the transaction.
checked_sub for money
Financial underflow must abort. checked_sub returns Err on underflow. Wrong choice = silent corruption.

07
Security architecture
8 attack vectors — all blocked
Missing signer
Call instruction without signing as expected wallet
pub authority: Signer<'info>
PDA substitution
Pass own PDA where victim's router account is expected
seeds=[...], bump=router.bump, has_one=owner
Timestamp forge
Pass fake past timestamp to claim non-existent heartbeats
Clock::get() — validator-set, unforgeable
Same-block replay
Resubmit a valid heartbeat transaction in same block
require!(elapsed > 0, HeartbeatTooSoon)
Integer overflow
Pass u64::MAX to wrap a balance silently to zero
checked_add().ok_or(Error::Overflow)?
Unauthorized admin
Sign with non-authority wallet for governance operations
require!(signer.key() == protocol.authority)
Type confusion
Pass Router account where Protocol account is expected
Discriminator mismatch → AccountDidNotDeserialize
Insecure CPI target
Pass malicious program ID as token_program argument
pub token_program: Program<'info, Token>
Signer proves identity (authentication). Manual require! proves permission (authorization). Both are always needed — one without the other is a vulnerability.

class RouterSimulator { async sendHeartbeat() { // simulate real-world failure rate if (Math.random() < this.failRate) { this.missedCount++; return false; // router offline } await program.methods .heartbeat() .accountsPartial({ router: this.routerPDA, protocol: this.protocolPDA, owner: this.wallet.publicKey, }) .signers([this.wallet]) .rpc(); } } // all routers run in parallel await Promise.all( simulators.map(s => s.start(INTERVAL)) );
Why .accountsPartial() not .accounts()? Anchor 0.30+ auto-resolves accounts from IDL. Router PDA needs router_id (a runtime string) in seeds — auto-resolver cannot handle this and enters infinite recursion. accountsPartial provides exactly what we specify.
10
Architecture rationale
Why these decisions
One PDA per router
Parallel Sealevel execution
Vec in shared account hits 10MB + forces serial writes. Individual PDAs → Solana processes all heartbeats simultaneously. One bug can't corrupt all devices.
Canonical bump storage
Correctness + compute savings
find_program_address iterates 255→0, costs compute each call. Store at init, reuse forever. Wrong bump = different address entirely.
GPS as fixed-point i64
BPF has no float support
Multiply coordinate ×1,000,000. 6 decimal places = ~11cm precision. Bounded: ±90° lat (physical GPS limit), ±180° long.
Asymmetric score
+1 on time, −10 late
One miss = 10 recoveries. Forces genuine continuous uptime. Operators cannot game with burst heartbeats after offline periods.
overflow-checks = true
Cargo.toml safety net
Rust release mode silently wraps overflow. u64::MAX + 1 = 0. In a financial program catastrophic. One line prevents the entire class.
uptime.rs separation
Pure math module
No Solana deps — testable with cargo test, no validator. 12 unit tests. Reused by reward engine. heartbeat.rs stays clean.
Vault not minting
Controlled supply
Minting = inflation risk. Pre-funded vault = distribute only deposited SOL. Admin controls economics externally. Vault empty = rewards stop cleanly.
Auth + authz separate
Signer ≠ authorized
Signer proves identity. require! proves permission. Authentication ≠ authorization — both always needed together in every admin instruction.
vault_bump in Protocol
Computed once, stored
Vault is UncheckedAccount (SOL only). Bump computed via find_program_address at init, stored as protocol.vault_bump, reused in every claim.
