The problem

Operators self-report uptime

Wi-Fi infrastructure networks pay operators for keeping hardware online. The payer has no independent way to verify that the hardware actually was online — so the number that determines payment is supplied by the party being paid.

Trust

The network takes the operator's word for uptime.

No consequence

Underperforming costs nothing, so nothing enforces quality.

No audit trail

Disputes have no shared record to resolve against.

RouterPulse replaces the self-report with a signed heartbeat the operator cannot forge, collateral they can lose, and an on-chain record anyone can check.

The bug that caused a rewrite

The first version paid on a lifetime average

// original — looks reasonable, is exploitable
reward = elapsed_time × reward_rate × lifetime_uptime_percentage

lifetime_uptime_percentage came from counters on the router account. When a router stopped sending heartbeats, nothing recomputed it — there is no cron on a blockchain.

The exploit

Build a good history, then go dark permanently. The average still reads ~100%, and rewards keep accruing for time spent offline.

The fix wasn't a patch — it was a re-architecture. Rewards are now scoped to a closed epoch. An epoch a router didn't participate in has no record, so there is nothing to claim. The exploit isn't guarded against; it's structurally impossible.

Architecture

Solana is the source of truth. Always.

Solana devnet ← source of truth │ ┌──────────┴───────────┐ backfill live websocket (getSignaturesForAddress) (onLogs) └──────────┬───────────┘ ▼ processSignature() ← ONE code path, idempotent │ ┌──────────┼────────────────┐ ▼ ▼ ▼ events routers/epochs transactions (append- (projections) (idempotency gate) only) ▲ │ reconcile.ts — re-reads chain accounts on an interval, overwrites the projection, logs drift │ ▼ Redis pub/sub ─► NestJS API ─► Next.js dashboard

MongoDB is a projection, never the truth. Reconciliation exists because the event stream can lose data — and in this project it demonstrably did.

Lifecycle

From onboarding to payout

① Two identities

A device key signs heartbeats, distinct from the owner wallet. Steal the hardware and you get a key that can only say "I'm alive" — never move funds.

② Collateral gates activation

heartbeat refuses to activate a router below min_stake. You cannot slash someone who staked nothing.

③ Heartbeats, scoped

Each lands in the RouterEpoch PDA for the current window — not a running total.

④ Finalization

Permissionless crank. Reads only public state, writes a pure function of it — so anyone can close an epoch.

⑤ Claim mints nothing

Creates a vesting entitlement. Total supply does not move.

⑥ Vesting is the only mint path

claim_vested is the sole instruction that increases supply, and only by what has actually vested.

Economics

One table pays and punishes

UptimeReward multiplierSlash
≥ 99%100%—
95 – 99%90%—
90 – 95%75%1%
80 – 90%50%5%
70 – 80%25%8%
< 70%0%10% of stake

Reward and slash come from the same lookup on purpose. Marginal downtime is survivable; sustained downtime is expensive. That asymmetry is the entire economic argument for keeping hardware online.

Slashed collateral is burned, not redistributed — so the penalty is deflationary for every holder rather than a transfer to whoever controls the treasury.

The good part

Six bugs found by running it

#BugWhy it matters
1BPF stack overflowThe build printed an error and still emitted a working .so. Trusting the exit code ships undefined behaviour.
2Bootstrap deadlockStaking needed tokens; minting needed vesting; vesting needed staking. Nobody could ever get the first token.
3Indexer losing eventsA transient RPC null marked a signature processed forever.
4u64 overflowOverflowed at a 100% multiplier. Caught by its own unit test.
5listen() on localhostGreen deploy, 404 everywhere. The header told the truth while the status code lied.
6Foreign UNIQUE indexIncompatible with PDA-based identity — two operators may share a router ID.
Bug 3 is why reconciliation exists here. The event stream genuinely lost data — the periodic re-read from chain is what caught it. That's not a failure mode I designed around defensively; it's one I watched happen.
Deep dive

Bug 3, in full

// indexer/src/ingest.ts — the original
if (!tx || tx.meta?.err) {
    // treats "not queryable yet" the same as "reverted"
    await claimSignature(...);   // ← permanent
    return 0;
}

A log notification routinely arrives before the RPC will serve the transaction. That null is transient — but the signature got recorded as processed, and backfill skips anything already recorded. The events were unrecoverable.

What it looked like in production

An epoch sat in MongoDB marked claimed: true with no reward, no uptime, no finalized flag — while the chain had it fully finalized at 10000bps / 240000000.

Two fixes. Don't claim a signature on a transient null. And extend reconciliation to cover epochs — it only covered protocol and routers, which is exactly why nothing repaired the damage.
